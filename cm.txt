The auth note is replaced with the full diagnosis, because it bites every script
in the repo:
  1. ~/.kaggle/kaggle.json is STALE -- auth succeeds, the first real call 401s.
  2. ~/.kaggle/access_token is the working credential, and that path makes a
     network call (_introspect_token) on every authenticate().
  3. kaggle/__init__.py runs api.authenticate() at IMPORT time, so
     "from kaggle.api.kaggle_api_extended import KaggleApi" can raise SSLError
     from the import itself, outside a try that only wraps the API object.
So: do not delete access_token (tried -- it drops us to the stale kaggle.json and
401s); put the import INSIDE the retry loop; the failures are intermittent, so
retrying is correct and no config change is worth making.
