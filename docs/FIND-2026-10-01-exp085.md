and it embeds at 224 (cheap) rather than 384.

## 3. ⚠️ The blocker, stated plainly

**The code is not public.** `t88take/rsna-knee-code` (referenced by the manifest as the place the
config/backbone live) returns **403 Forbidden**, and all 27 of `t88take`'s public kernels are from
other competitions — there is no public notebook with the model definition.

So the **weights are fully in hand and the forward pass is not**, and the shapes constrain it only
partly: `slice_pool` is evidently a depth-conditioned attention pool, and `head.out = Linear(256,12)`
with `head.query (12,256)` looks like a per-finding classifier applied to that finding's own 256-d
feature — but the exact ordering of norm / depth-add / softmax / slot mixing **cannot be read off the
shapes**, and two unknowns at once (the forward *and* the slice preprocessing) are hard to separate:
if a reimplementation scores 0.85 instead of 0.9062, we cannot tell which half is wrong.

## 4. What would make it usable, in order of cost

1. ⭐ **Ask the two questions that collapse the search.** The config dict names the *exact* recipe
   (`band_groups`, `n_group 4`, `per_study`, `crop_mm 130`, `slice_depth_range (0.2,0.8)`,
   `center`). Slice selection from those is reconstructible; **the head's forward is not.** Finding the
   author's `infer.py` (or a discussion post) is worth more than an hour of guessing.
2. **Constrain the forward with a known-answer test.** Run the reimplementation on *our* cached
   volumes and require **gold58 ≈ 0.9062**. That single number validates forward *and* preprocessing
   together — but only if the slices are right, which is why (1) matters.
3. **Fall back to the members whose code IS public.** `apoorvadixit/rsna-knee-weights-v4cx` is
   `convnext_small.in12k__latL__v4cx{0..4}_best.pt` (199 MB x5) — a **timm ConvNeXt-small**, i.e. a
   standard architecture whose forward is not in question, so only the head needs matching.
   `soyaoki/rsna-knee-my-models` is a 5-fold set (89 MB/fold, `_epoch5`/`_epoch10` variants).
   Neither has a published score, so each costs a CPU gate to price.
