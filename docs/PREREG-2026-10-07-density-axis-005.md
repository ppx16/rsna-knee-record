## 1. 为什么选"切片采样密度"这条轴

它是**全项目唯一被两个独立仪器、双向量化过**的 ≥0.005 机制：

| 来源 | 仪器 | 效应 |
|---|---|---|
| 作者自己的表（`raptor-knee-finespacing` 数据集描述） | 公榜 solo | 44 层 → 0.926；64 → 0.928；**80 → 0.932** ⇒ **+0.006** |
| 我们自己的 `gap0` | 本地 OOF | ±1 相邻 → ±2 隔层 = **−0.012**，CI [−0.0041, −0.0199]，baseline 赢 99% bootstrap |

两者同轴、同号（更密更好）、同量级。而且作者把**机制**说清了（逐字）：
> *"Widening the span only pays if slices are added to keep the sampling dense"* —— 摊薄到 44 层 = 0.917，而同样宽跨度放 64 层 = 0.928。

**80 槽的精确定义**（`scripts/ens_experiment.py` line 801，与作者描述逐字一致）：
```
_SLOTS80 = [("Sagittal", 1, 22), ("Sagittal", 0, 18),
            ("Coronal", 1, 15), ("Coronal", 0, 10), ("Axial", -1, 15)]   # sum = 80
span (0.02, 0.98) · img 336 · crop 140 mm · k_eval 78
```
对比我们构建器现有的 64 槽表 `(18/14/12/8/12)`：**同样 5 组、同平面、同侧、同顺序，只是每档更多切片** ⇒ 语料构建器（`kernels/kernel-corpus64/build_corpus.py`，`pick_indices(n,k,span)` 的 `k` 本就是参数）**只需改 2 行**。

## 2. ⛔ 但我先要反对自己：solo 效应**不蕴含**集成效应

**这是必须先解决的反证，不解决就不该建语料：**

- **v9 就是作者的 80 槽模型**（0.932 solo）。我们**已经有它**。
- 而 **D14 实测：把它当第 5 个视角加进集成 → 两次独立尝试、两次 0.941 平**（`add-finespacing-arm` 与 `add-widedense-arm` 都是）。
- ⇒ **"某个臂 solo 更强"在这里【不】转化为"集成更强"**（与 A167 的 11× 衰减律、C14 的"多样性 ≈ +0.001"一致）。

**所以"我们自己再训一个 80 槽臂"最可能的结局是：复现一个 0.932-solo 的臂，而它加进去是平的。**
⇒ **在花掉 8 个分片的语料构建之前，必须先用一个便宜实验判掉这个可能。**

## 3. 第一步（便宜、可判、先做）：在**大 n 仪器**上量密度轴

**关键**：我们**已经有 44 槽与 64 槽两档语料**，不需要建任何东西就能测这条轴在**集成相关口径**上的效应。

- **仪器**：881 研究 fold-0 held-out（同口径 `msft2` = **0.8847**、从零 3D = **0.6493**）。**分辨率 ±0.004**，够判 ≥0.005。
- **对比**：44 槽臂 vs 64 槽臂，**同一架构、同一配方、只差槽数与跨度**（`SPAN44 = (0.152,0.847)` vs `SPAN64 = (0.02,0.98)`，`build_corpus.py` line 58-59 已有）。
- **判据（预登记）**：
  - **64 槽臂 − 44 槽臂 ≥ +0.005 且 CI 不含 0** ⇒ 密度轴在**集成相关口径**上真实 ⇒ **值得**建 80 槽语料。
  - **< +0.005 或 CI 含 0** ⇒ **密度轴到此为止，不建 80 槽语料**，转去找别的 ≥0.005 机制。
- **注意**（避免读错）：这不是在测"作者的表对不对"，而是在测**它在我们自己的大 n 仪器上、以我们自己的配方**是否复现。作者的表是公榜 solo；我们的仪器是本地 held-out。两者不必相等。
