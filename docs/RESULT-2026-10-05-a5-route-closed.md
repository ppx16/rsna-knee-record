# RESULT 2026-10-05：A153 的实验算出来了（+0.0283 存活），**但它同时把这条路否掉了**

## 1. 先给结论

**A153 要求的那个"补上同一种增强再对打"的实验通过了它自己的门槛**（Δ=+0.0283 ≥ +0.02，P=1.000）。
**但把两条臂放进【我们全部成员】的同一口径里一比，A5 路线立刻死了** —— 因为 A-lite 两条臂的绝对水平
比我们已有的成员低 **0.13–0.16**，而门槛是 solo ≥ ~0.90。**6×16 缓存不造，TPU 不花。**

## 2. A153 的实验（数据早就在 Kaggle 上，只是从没算过）

三个 `a5lite` 内核只差 prelude 一行 argv，`a5lite-r` 就是"我们的 head + 同样的增强"那条对照臂：

```

kernel-a5lite-r   --head raptor --k 12       --aug 1 --tag rfa    COMPLETE, 881-study OOF
```

| 臂（都带 `--aug 1`）| macro ROC-AUC |
|---|---|
| A5 架构（`a5fa`）| **0.7053** |
| 我们的 head（`rfa`）| **0.6770** |
| **Δ** | **+0.0283** |

```
配对 bootstrap（按研究重抽 400 次）：mean +0.0289  95% CI [+0.0172, +0.0401]  P(A5>raptor) = 1.000
12 个标签里 11 个同向（只有 Effusion −0.0105）
```

**⇒ 按 A153 自己写下的规则（"哪怕降到 +0.02 ⇒ 缓存才值得造"），这一步是【通过】的。**

## 4. 顺带得到的三件东西

1. **一个可复用的仪器**：`work/rank_all_members_one_convention.py` 把本地**全部** OOF 放到一个口径上排名。
   以后任何新成员都能**先在这里定位**，再决定值不值得花算力 —— 这正是本次省下 6.9 h TPU 的方式。
2. **一条一致性校验**：**`msft2` 在这张表里是我们最好的成员（0.8847）**，而它正是唯一一条产生了实测名次增益的臂
   （格内百分位 38.89%→13.66%）。**两条独立读数互证。**
3. **`d3f0` 的位置值得注意**（0.8380）：它是"我们的 head + 真训练器"，比 `cn0` 低 0.025、比 `msft2` 低 0.047。
   ⇒ A153 当年那句"`rf0` 比 `d3f0` 低 0.116 是被【增强】这一个变量带偏的"，**在无掩码口径下仍成立**
   （`rfa` 0.6770 vs `d3f0` 0.8380 = −0.161）。
