
### 10.5 The fourth kernel's failure, confirmed and attributed

`rsna-knee-exp085-axis` finished in **ERROR**. Its log is one line:

```
!! exp085 fold0.pt not mounted
```

**That is this kernel's own guard, firing exactly where it should** — the checkpoint dataset was
dropped from the push (§10.1), so the run stopped before loading anything.

⚠️ **Two things worth separating:** (a) the *cause* is the withdrawn dataset, not a defect in the new
axis/intensity variants — **that code was never executed**, so it is syntax-checked and unproven
rather than wrong; (b) **the guard is the reason the failure is readable**. A kernel that built the
model first and discovered the missing file inside a traceback would have produced the same ERROR
status with a far worse diagnosis. `raise SystemExit("!! ... not mounted")` on a required input is
worth the four lines it costs.

⚠️ **And the push said "successfully pushed".** The only reason this did not become another
swallowed failure is that the warning text — *"The following are not valid dataset sources and could
not be added"* — was read. **`kernels_push` cannot be trusted to fail; its output must be read.**
